Learning Course

A four-stage path to a working robot.

Start with Setup if you've never used CAD. Otherwise, jump to whichever stage matches where you are. Stages build on each other — skipping ahead is allowed but you'll backtrack to fill in gaps.

i
How this page is organized

Each stage is a checklist. Lessons inside a stage are meant to be done in order. The whole course assumes Onshape and goBILDA / REV hardware — the principles transfer, but the screenshots won't.

0 Course Setup ~30 min total

Three short pages. Pick the one that matches your starting point — you don't need all three.

  • New to CAD — what it is, why teams use it
  • New to Onshape — account, browser setup, document basics
  • Required course tools — libraries, links, accounts
1 Stage 1 · Foundations ~6 hours

The CAD vocabulary and FTC-specific concepts you'll use in every later stage. Don't skip it.

  • Focusing on improvement — how to learn from a design
  • Onshape fundamentals — sketches, parts, assemblies
  • Power transmissions — gears, belts, chain
  • Practice mechanisms — small builds to apply each idea
  • Design methodology — defining the problem before drawing
  • Subsystem workflow — one studio per subsystem, top-down
2 Stage 2 · Build four subsystems ~12 hours

Apply Stage 1 to four canonical FTC mechanisms. Each is a complete, parametric design you'll fork and modify.

  • Mecanum drivetrain — chassis, motors, wheels
  • Dead-axle pivot — a one-motor arm that doesn't twist
  • Active intake — compliant wheels, geared together
  • Cascade slide — vertical lift with rigging
3 Stage 3 · Full-robot integration In progress

Putting subsystems together: layout sketches, packaging, top-down workflow. The skill that separates a working robot from a working subsystem.

  • Robot layout sketches
  • Packaging within the 18" cube
  • Wiring as a design problem
  • Battery and electronics placement
4 Stage 4 · Strategic design Coming soon

Game analysis, scope decisions, and design for reliability. Why do some teams pick the right mechanism and others spend the season iterating?

  • Game analysis frameworks
  • Scope and tradeoffs
  • Designing for reliability
  • Iteration vs. revision
